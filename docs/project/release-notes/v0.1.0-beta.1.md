# spotussi v0.1.0-beta.1

The first release: a fast, self-hosted listening-stats dashboard for one Spotify account. One binary with the web UI built in, one SQLite file, one container. This is a beta: try it, keep backups, and expect changes before 1.0.

## Install

- **Docker:** `ghcr.io/jasoncronje/spotussi:0.1.0-beta.1` (linux/amd64, linux/arm64, distroless, about 8 MB to download). [docs/install.md](https://github.com/jasoncronje/spotussi/blob/main/docs/install.md) has a Compose file, Traefik labels and a forward-auth example.
- **Binaries:** static builds for Linux and macOS (amd64, arm64) below, with `SHA256SUMS`. The macOS builds are not notarized.

No settings are required: start it, open the UI, and the setup wizard takes you through the owner password, your own Spotify app (the wizard shows the exact redirect URI) and the connection.

## What's in it

- **Live capture.** Polls the player while you listen and records how long you actually listened, skips, device, context and shuffle. A recently-played check every 20 minutes catches plays the poller missed.
- **History import.** Upload Spotify's Extended Streaming History export (zip or JSON) in Settings or the wizard, or run `spotussi import`. Every row is kept; re-imports only add what's new. A lifetime export of about 300k rows imports in under 20 seconds.
- **Merged, honest numbers.** Live and imported plays are merged without double counting, with per-play provenance. One play rule (30 s by default, configurable) applies to every source; every view has a Plays/Time toggle.
- **Dashboards.** Overview, top tracks, artists, albums and genres with rank movement, stats over time, artist, album, track and genre pages, history with filters, longest sessions, a time-range picker on every page and your own time zone. Answered in milliseconds at any history size: on a 500k-play reference dataset the slowest dashboard endpoint has a p95 under 20 ms and a full rebuild takes 5 to 8 s.
- **Artwork and metadata.** Looked up most-played first. Spotify is the primary source; Spotify oEmbed, Deezer and MusicBrainz fill in artwork, durations, release dates and genres while Spotify's lookup quota is spent.
- **Access control.** Owner password (default), single sign-on through a forward-auth reverse proxy, or no login for private networks. Read-only API tokens for scripts and AI clients, revocable one by one.
- **API.** The read-only `/api/v1` the UI itself uses, documented at `/api/docs` on your instance.
- **MCP server.** `/mcp` (Streamable HTTP, API-token auth) lets AI assistants answer questions about your listening with the same numbers as the UI; `spotussi mcp` is a stdio proxy for clients without HTTP support. See `docs/mcp.md`.
- **Backups.** `spotussi backup` and a download in Settings write a consistent, integrity-checked snapshot while the server runs; `spotussi restore` swaps one back in safely.

## Known limits

- **Spotify's catalog lookup quota.** Spotify gives apps like this a small daily quota for track and artist lookups (about 500 a day, measured in October 2026; Spotify doesn't publish the number). Live capture is not affected, but filling in a lifetime export from Spotify alone would take months. The fallback sources below cover most of it within hours.
- **Fallback metadata is matched by name.** Spotify oEmbed is exact (by URI). Deezer and MusicBrainz are matched by title, artist, album and duration; low-confidence matches are rejected, so some tracks keep no duration, release date or genre until Spotify's quota allows a lookup. On one large export Deezer matched about 98% of the top 1,000 tracks and 90% of the rest; MusicBrainz has genres for about two thirds of matched artists. Fallback genres use MusicBrainz names, so they are broader than Spotify's.
- **You need your own Spotify app and Premium.** Spotify no longer allows shared apps for tools like this. Over plain HTTP the connection uses a copy-and-paste step (Spotify only accepts `127.0.0.1` for plain-HTTP redirects); HTTPS behind a reverse proxy avoids it.
- **The Extended Streaming History is required for past listening.** It can take Spotify up to 30 days to send. The basic Account Data package is not supported.
- **Music only.** Podcasts, audiobooks and videos are kept in the raw data but not shown or counted yet.
- **One account per instance.** No multi-user or social features.
- **Capture depends on the server running.** Spotify keeps only the last 50 recently played tracks; plays older than that from a long outage come back only through a later export import.
- **The instance key is not in backups.** `DATA_DIR/key` encrypts the Spotify connection; copy it once. Without it a restored instance needs a Spotify reconnect.

## Compatibility

The API stays at `/api/v1`, but during 0.x it may change in breaking ways; each release's notes list any breaking change. The stability promise (breaking changes only in a new `/api/v2`) starts at 1.0. The database is migrated forward automatically; back up before upgrading, since a newer database can't be opened by an older release.
