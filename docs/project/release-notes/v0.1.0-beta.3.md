# spotussi v0.1.0-beta.3

Library sync, a faster metadata pass and a data sources switch. Updates [v0.1.0-beta.2](https://github.com/jasoncronje/spotussi/blob/main/docs/project/release-notes/v0.1.0-beta.2.md).

## Install or update

- **Docker:** `ghcr.io/jasoncronje/spotussi:0.1.0-beta.3` (linux/amd64, linux/arm64). `:beta` follows the newest beta.
- **Binaries:** static builds for Linux and macOS (amd64, arm64) below, with `SHA256SUMS`.

Back up before updating (`spotussi backup`, or Settings → System). This release migrates the database forward (ListenBrainz metadata and library tables, migrations 0009 and 0010).

**Reconnect Spotify once after updating.** The Library page needs one more read-only permission, `user-library-read`. Until you reconnect (Settings → Spotify, then approve the consent page), playlists sync and everything else works as before, and the Library page says the permission is missing.

## Changes

- **Library.** A new Library page compares what you saved with what you play: saved songs you never played, how many days saved songs took to reach their first play and heavy rotation (the 5th counted play), saves and removals over time, saved albums and how much of each you played, and your playlists with how much of each you play and how often you start them. A playlist page lists its songs in order, with who added each on collaborative playlists. Track pages show when you saved the track. Settings → Spotify shows the library sync and has **Sync now**.
- **Library sync.** A quick check every hour (about 3 requests when nothing changed) and a full pass once a day, outside Spotify's daily lookup quota. Saved and playlist songs fill in names and artwork without lookups. Since February 2026 Spotify shares the songs of your own and collaborative playlists only, so followed playlists show their plays but not their songs. `LIBRARY_SYNC_ENABLED` and `LIBRARY_SYNC_INTERVAL` control it.
- **Faster genre and artist lookups.** A new ListenBrainz pass runs before MusicBrainz and finds most artists' MusicBrainz IDs and genres in batches, so the slow 1-request-a-second MusicBrainz stage only looks up what it missed (about 3 h instead of 6.5 h for a whole catalog). `METADATA_LISTENBRAINZ=false` turns it off.
- **Data sources switch.** Settings → General → Display has a per-browser switch, off by default, that shows where each play and track detail came from: Overview's source meters, History's per-play source lamps and the "Provisional details" badge.
- **Album artists.** Album pages list the artists on the album when three or more appear on its tracks.
- **Source code link.** Settings → System links the source code, as AGPL-3.0 asks of network-facing instances.
- **MCP:** a `get_library` tool answers questions like "which songs did I save and never play?".

## Compatibility

Additive API changes: `listenbrainz` in the fallback source and provenance enums, `/library/*` endpoints, `POST /library/sync`, `saved_at` on track pages, and `library` and `scopes` in `/system/status`.

## Known issues

- **Reconnect shows "Connected" instead of the consent page.** Settings → Spotify → Reconnect skips straight to the connected panel for an account that is still connected, so you can't grant `user-library-read` from there. Fixed in the next release. Until then, disconnect and connect again in Settings → Spotify (recorded plays stay), or ask your instance for a fresh consent link with `POST /api/v1/spotify/authorize`.
